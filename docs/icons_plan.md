# Keenly 技能图标量产方案（规划）

战棋游戏技能图标生产线：小尺寸、大批量、四主色系 + 辅助色，
矩形 / 圆角矩形遮罩，单进程批量出图，位级门禁继续成立。

状态：**已定案**（决策记录见第 7 节），待开工 Phase 1。

---

## 1. 尺寸与格式规格（建议定案）

| 档位 | 尺寸 | 用途 | 说明 |
|---|---|---|---|
| **主力** | **128 x 128** | 技能栏 / 卡面主图标 | 生产母版，1:1 |
| 次档 | **64 x 64** | 小技能位 / 列表 | **直渲**，不是缩放（见下） |
| 缩略 | 32 x 32 | 角标 / buff 条 | 直渲，仅保留剪影层 |
| 可选 | 128 x 96 / 96 x 128 | 卡面横幅 / 竖栏 | 需要时再开，遮罩逻辑不变 |

**格式**：8-bit RGBA PNG（图标不需要 16-bit；保留 sRGB 编码 + TPDF dither
防渐变 banding）。alpha = 遮罩覆盖率（边缘 ~1px smoothstep 抗锯齿），直通
（straight）alpha，引擎导入即可。

**形状遮罩**：两种，`--mask rect|round`
- 直角矩形：硬边 + 1px AA；
- 圆角矩形：圆角半径三档 `--radius 0.10 / 0.20 / 0.30`（相对 min(w,h)）。

**为什么是 128**：游戏 UI 图标常用 64~128；128 是 64 的整数倍源（HiDPI/mip
友好），单张 16K 像素渲染成本可忽略（见 §5）；比 256 省 4 倍包体与显存。
「小尺寸」的正确做法不是渲染大图再缩，而是**按目标尺寸直渲**——Keenly 的
像素是 `(x, y, w, h)` 纯函数，几何分辨率无关，直渲 64px 比 128→64 重采样更锐。

**尺寸自适应的后期参数**（重要细节）：
- `grainScale` 随尺寸线性缩放：`grainScale *= size / 128`（128px 上 2.5 的
  聚团，在 64px 上应是 1.25，否则颗粒相对图标过大）；
- `grain` 幅度在 32px 档减半（小图上颗粒会糊成噪点）；
- `view / warp / relief` 不随尺寸变（几何本身分辨率无关）。

## 2. 色系定义

四个主色系。每个色系 = **6-stop 调色板 × 场生成器偏好 × 后期默认 ×
点缀色规则**，全部写进 preset 表（`keenly.cu` 的 applyPreset 扩展）。
「辅助色」= 图标内的点缀色（描边 / 高光 / 辉光 / 暗角），不设独立色系。

### 主色系

| 色系 | 语义 | 调色板走向 | 场生成器偏好 | 符号填充 / 描边 / 点缀 |
|---|---|---|---|---|
| **蓝** | 冰霜 / 奥术 / 雷 | 深海蓝黑 → 钢蓝 → 冰青 → 白 | warp（流体） | 冰白填充、白描边、青色辉光 |
| **红** | 火焰 / 战争 / 血 | 暗酒红 → 猩红 → 橙金 → 米白 | liquid（流体+高光）, warp | 象牙填充、金描边、金色火星 |
| **金** | 神圣 / 光明 / 王权 | 深青铜 → 赭金 → 明金 → 象牙白 | warp（流体） | 白圣光填充、白描边、青铜阴影 |
| **紫** | 暗影 / 虚空 / 秘能 | 暗紫黑 → 紫 → 品红 → 淡紫白 | warp（流体） | 淡紫白填充、品红描边、洋红辉光 |

> 背景统一用**流体家族**（warp 有机流动 / liquid 流动+高光）：Worley 系
> （frost/facet）在图标尺寸下是难看的 Voronoi，图灵斑也不做图标背景。
> 「好看来自构图与调色，不是形状语言的种类」——形状语言统一，靠色系拉开。

### 点缀色规则（每色系一套，随 preset 下发）

| 点缀角色 | 用途 | 各色系取值方向 |
|---|---|---|
| 描边色 | 符号/边框亮描边 | 蓝=冰白、红=金、金=象牙白、紫=品红 |
| 高光色 | 符号体积光 / glint | 色系内最亮档（+微暖/微冷偏移） |
| 辉光色 | halation / 外发光 | 蓝=青、红=橙金、金=暖白、紫=洋红 |
| 阴影色 | 符号内侧 / 边框暗部 | 色系最暗档加深（低饱和冷/暖偏移） |

### 可读性规则（64px 剪影纪律）

技能图标在 64px 甚至 32px 必须一眼可辨，这是硬约束：

1. **符号-背景对比**：符号填充色取色系内最亮档（或互补点缀色），背景中部
   亮度整体压暗 0.85x，保证轮廓对比 ≥ 3:1（可用统计脚本量化验证）；
2. **描边**：所有符号带 2px（@128）亮描边，颜色 = 色系点缀色；
3. **线宽下限**：符号笔画 ≥ 5px @128（≈ 2.5px @64），细节层数 ≤ 3；
4. **颗粒在符号区内减弱**：符号内部 grain 乘 0.5，避免图案被颗粒吃掉。

## 3. 图标构成模型

一张图标 = **色系 × 背景场 × 符号 × 边框等级 × seed**

```
[背景层]  field 生成器 + 色系调色板 + 宏观构图（现有管线）
[符号层]  SDF 图元合成的技能图案（新增）—— 填充 + 描边 + 体积光
[边框层]  矩形/圆角矩形框 + 等级装饰（新增）
[遮罩层]  rect / rounded-rect alpha（新增）
[后期]    现有 post 链（颗粒/光晕/调色/ACES），符号区颗粒减弱
```

### 符号库（SDF 图元合成，首批 ~28 个）

图元能力：圆 / 圆环 / 胶囊线段 / 圆角盒 / 多边形折叠（3/4/5/6 边，固定角度
常量，bit-exact）/ 弧 / 极坐标折叠星形。组合用 min/max（union/sub），
辉光用 powi 距离衰减——全部多项式 + IEEE sqrt，位级门禁不破。

| 组 | 符号 |
|---|---|
| 武器 | 剑、斧、弓箭、匕首、锤、矛 |
| 防御 | 盾、盔、锁链 |
| 元素 | 火焰、水滴、雪花、闪电、水晶、藤叶、波浪、岩石 |
| 奥术 | 星芒、月牙、日轮、魔眼、虚空螺旋、符文环 |
| 状态 | 心、骷髅、治疗十字、药瓶、翼、王冠 |

### 边框等级（顺带服务稀有度 UX）

| tier | 样式 | 典型用途 |
|---|---|---|
| t1 | 单细描边 | 普通技能 |
| t2 | 双倒角 + 四角钉 | 高级技能 |
| t3 | 内辉光 + 角饰 | 稀有技能 |
| t4 | 宝石嵌角 + 外发光 | 传说技能 |

### 配额表（避免「全笛卡尔积」的雷同）

不是每个符号 × 每个背景都出；每色系一张 curated 配额表：

- 每色系 **40 张**：10 武器/防御符号 + 14 元素/奥术符号 + 8 状态符号 +
  8 张同符号不同 tier/背景的变体；
- 合计 **4 × 40 = 160 张**，manifest 驱动，可随时扩到 300+。

seed 纪律：`seed = hash(family, glyph, tier, variant)`，manifest 里显式列出，
换 seed 出变体、风格不变——和现有「系列出图」哲学一致。

## 4. 工程实现（分阶段）

### Phase 1 — 核心扩展（1~2 个会话）
- `src/sdf.cuh`：SDF 图元 + 组合算子 + 辉光衰减，纯 `__host__ __device__`；
- `src/icon.cuh`：遮罩 / 边框 / 符号层 / 合成规则（GPU/CPU 共享，门禁继续成立）；
- `png_writer.h`：RGBA 输出（+alpha 通道，filter 0，stored DEFLATE 不变）；
- preset 扩展：`gold`、`violet` 新增，`cinema/ice/ember/dusk` 微调为
  图标版（含 §2 点缀色字段）。

### Phase 2 — 批量产 CLI
- `keenly --icons manifest.csv --outdir out/icons`：**单进程**批量出图
  （一次 CUDA init、buffer 复用、逐张写 PNG）；
- manifest 列：`family, glyph, tier, variant, seed, size, mask, radius, mode, ...`
  → 确定性复现整套图标；
- 命名规范：`out/icons/<family>/<glyph>_t<tier>_v<variant>_<size>.png`。

### Phase 3 — 预览与调优
- 每色系 contact sheet（N 宫格，扩展现有 runGrid）；
- 统计脚本（沿用 `out/grid_stats.py` 思路）：符号-背景对比度、直方图形状、
  64px 缩略可读性抽查；
- 每轮调整记入 `docs/experiments.md`（项目纪律）。

### Phase 4 — 门禁升级
- `--check-all` 覆盖 icon 着色路径（含 SDF 组合，要求 maxAbs == 0）；
- `verify.ps1` 增加图标冒烟（1 张 × 4 色系 + 1 张圆角遮罩 + 1 张直角遮罩）。

### Phase 5 — 可选增强
- 图集打包：4096² atlas + JSON 框数据（引擎侧免裁剪）；
- PNG fixed-Huffman 压缩（路线图既有项，包体缩 2-5x）；
- 32px 档专用「剪影简化层」（自动降细节）。

## 5. 性能预算

| 项 | 数值 | 依据 |
|---|---|---|
| 单张 128² field | ~0.2 ms | 现管线 2.7Mpx ≈ 36ms → 16Kpx 线性外推 |
| 单张 post | ~0.02 ms | 同上（1.5ms / 2.7Mpx） |
| 160 张 GPU 合计 | **< 0.1 s** | 渲染从来不是瓶颈 |
| 160 张 PNG 写盘 | ~1-3 s | stored DEFLATE，64KB/张，I/O 主导 |
| 整包含门禁抽样 | **< 30 s** | 门禁按 (mode, glyph, tier) 组合抽样，不逐张跑 |
| 显存 | < 50 MB | 128² 单 buffer 192KB，复用即可 |
| 包体（160 张 RGBA8） | ~10-16 MB → Huffman 后 3-6 MB | |
| 运行时显存 | ~5 MB | BC7/ASTC 压缩 + mip，单张 ~20KB |

**门禁抽样**（性能细节）：现在每次渲染都跑 320×180 CPU 参考（~0.1-0.3s），
160 张逐张跑会白花 30-60s。批量模式改为：每种 `(field mode, glyph, tier)`
组合抽样一次 + `verify.ps1` 阶段跑一次全量 `--check-all`。

**游戏运行时**：图标越小越省 fill rate 和显存；128 master + 64 直渲两张
足以覆盖桌面/移动端（引擎 mip 链自动生成 32/16）。shader 全是纯函数，
将来要「技能特效动态版」（逐帧换 seed 沸腾颗粒）也留了口子。

## 7. 决策记录

1. **符号层**：要做 —— 符号 + 纹理背景（SDF 图元合成，位级门禁保持）。
2. **输出形态**：单张 RGBA PNG，引擎自行导入；图集留作 Phase 5 可选项。
3. **辅助色**：不设独立色系，作为**图标内点缀色**（描边/高光/辉光/阴影）
   随每色系 preset 下发，见 §2 点缀色规则表。
4. **数量档位**：默认 4 色系 × 40 张 = **160 张**。要 300+ 或先小批试产
   （4×8）都可以，只改配额表。
