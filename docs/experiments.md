# Keenly 实验记录

每次改动后追加一条。格式：**改了什么 → 指标怎么变 → 为什么**。
只记有数据支撑的结论，不记猜测。

---

## 1 — GPU vs CPU 门禁的舍入底噪（2026-11-11）

**现象**：`keenly --check` 首跑 relL2 = 1.36e-05，超了随手定的 1e-5 预算。

**实验**：同一份代码，关掉 `--use_fast_math` 重测 → relL2 降到 6.15e-06。
说明底噪来源是 fast-math 的近似除法 + FMA 收缩（host/device 编译路径不同），
不是 bug——真实管线 bug 的量级在 1e-2 以上。

**教训**：verify 门禁的阈值要由实测底噪和真实 bug 量级共同决定，不能拍脑袋。
「relL2 必须是 0」在浮点世界是伪命题——当时是这么以为的，见实验 3。

---

## 2 — 舍入底噪随运算链长度增长（2026-11-11）

**改动**：quality 轮把 fieldPixel 从 3 次 field 求值加到 5 次（双尺度浮雕），
fBm 每 octave 加 4 次旋转乘加。

**现象**：门禁 relL2 从 1.36e-05 涨到 **6.5e-05**，接近当时 1e-4 的预算。

**分析**：FMA 收缩的舍入差是逐级累积的——运算链越长，CPU/GPU 的差异越大。
这不是代码质量问题，是预算模型太粗（只考虑了单点底噪）。

**教训**：门禁预算要为「未来更长的运算链」留余量，并且把测得的底噪机制
写进代码注释——否则每个后来者都要重新做一遍实验 1。

## 3 — 换 IEEE 数学，门禁升级为位级全等（2026-11-11）

**现象**：新增 bands 生成器（warpField 的三角波等值线）门禁直接失败：
relL2 = 2.6e-3、maxAbs = 6.9e-2，远超 2e-4 预算。frost 模式同时只差 9e-7。

**分析**：不是索引 bug。bands 的 fold 把上游浮点差逐级放大：×12 频率 →
折叠分支切换 → sstep 斜率 1.875 → 调色板 smoothstep 斜率 ~7.5，总增益约
126 倍。实验 2 的「预算随链长增长」模型挡不住这种**结构性增益**。

**解法**：改用严格 IEEE 数学（`--fmad=false`、不加 fast-math）。实测：
**全部生成器 relL2 = 0.000e+00、maxAbs = 0.000e+00**。

**决定**：门禁从「relL2 < 预算」收紧为「maxAbs == 0」，并作为项目铁律写进
CMake 注释。位级全等是最强的正确性声明，而且不再需要任何预算模型——
预算那套复杂度是 fast-math 的税。

**教训**：与其不断给误差预算打补丁，不如换一个让误差为零的编译约定。
「艺术渲染不在乎 1% 速度，在乎可复现」——性能 flag 是 per-target 的事。

## 4 — 用直方图抓「太平」的生成器（2026-11-11）

**现象**：新 liquid 生成器首版统计难看：亮度值域塌缩在 [0.06, 0.67]，
57% 的像素挤在同一个 octile——「液态金属」渲染成了灰色果冻。

**诊断**：不是 bug，是两个设计问题：(1) warpField 值域钟形集中，×0.9
后更窄，调色板两端根本够不到；(2) 高光是乘性的，palette 中间色 ×2 也
到不了白——而金属反射本质是**加性光**。

**修复**：场强 ×1.30；高光拆成乘性宽高光（powi 16）+ 加性白 glint
（偏暖，模拟钨丝反射）。复测：std 0.088 → 0.212，值域 [0.02, 0.89]，
高光 octile 占比 15%。

**教训**：生成器调完要看**直方图形状**，不只看均值方差：值域塌缩和
双峰分布是两种完全不同的「对」。prism 的双峰（31% 暗 / 28% 亮）正是
「凛冽」的量化特征。

## 5 — 反应扩散的种子尺度决定形态生死（2026-11-11）

**现象**：图灵斑（Gray-Scott）首版海报，f=0.0367/k=0.0649（斑点区）渲染出来
值域塌缩（std 0.015、100% 亮部）——「斑点」整个死了。同一对参数在 256 网格
活着（B std 0.116）。

**实验**：控制变量定位——C 渲染器在 rd-res 256 活（std 0.246）、512 死
（std 0.002）；numpy 同参数在 512/6000 也完全死亡（B = 0）。**不是代码 bug**：
GPU/CPU 两条路径忠实执行了同一套数学，是**初始化尺度**问题。旧 init 的种子
斑点半径是 res 的分数（0.012~0.030 × res），512 网格上种子半径 6~15 格，
Gray-Scott 动力学的内禀长度是格子单位——大块 B=1 种子在斑点区活不了，
在自复制的珊瑚区无所谓（所以 coral 一直正常，掩盖了问题）。

**修复**：种子半径改为格子单位（3~8 格，与 res 无关），rdRes 变成纯粹的
「图案密度」旋钮。复测：6 对参数全部存活。

**教训**：**迭代模拟的初始化有尺度语义**——「相对分辨率」的初始化在闭式
噪声里无所谓，在有内禀长度的动力学系统里会改变形态本身。res 缩放的是
「画多少格子」，不能缩放「每格的物理尺寸」。

## 6 — 反应扩散的映射中心要按形态区选（2026-11-11）

**现象**：条纹/蠕虫区（f=0.026/k=0.051 等）渲染偏暗偏平（58% 暗部）。

**分析**：B 的基线随形态区不同：斑点区 B≈0 + 热核，迷宫区 B≈0.25 均匀抬高
+ 细暗通道。旧映射 (0.20-b)×5 以 0.20 为中心，迷宫区整体压到负值域。

**修复**：映射改 (b-0.18)×4.5，「亮结构 + 暗地」极性，对全部形态区都落在
有效值域（实测 6 对参数 std 0.09~0.35，无塌缩）。

**教训**：场值映射的中心点是**形态区相关的经验参数**，不是常数——和实验 4
的直方图判据配合用：先看 B 场分布再定映射，别拍脑袋。

## 7 — PNG 流式写出：省的是内存，不是时间（2026-11-12）

**改动**：`png_writer.h` 从「整帧组 raw + 整帧组 zlib 向量再写盘」改为
流式——扫描线逐行进 64KB stored-block 暂存区，满了直接 fwrite（块边界
由已知的 raw 流长度预先算出，CRC32/adler32 增量更新）。

**验证**：8/16-bit、turing、RGBA 图标四条路径新旧输出 **SHA256 逐字节一致**
（同 65535 字节块边界、同 CRC/adler）。

**现象**：首测 2000x2832 16-bit 从 4.7s 降到 0.92s，看起来是 5x 提速——
但热态 A/B（新旧各跑两遍）是 0.64s vs 0.64s，**没有提速**。4.7s 是冷启动
假象（首次 CUDA context 创建 + 首次进程启动），不是 writer 的锅。真实
收益是峰值内存：70MP A1 写出时少掉 raw + zlib 两个全帧副本（~800MB）。

**教训**：**单次 wall-clock 测量会把冷启动算进被测对象**。A/B 必须热态
各跑多遍取稳定值，否则会为不存在的 5x 写一条假实验记录。顺带定位了真
瓶颈的大头：encode 链（每样本一次 `std::pow`）+ 两遍全帧串行扫描
（adler32/CRC32），见实验 8。

## 8 — encode 链并行化 + pinned D2H：写出阶段 2.7x（2026-11-12）

**改动**：(1) writeImage 的 sRGB+dither+量化从串行循环改为按索引区间
多线程（逐样本纯函数 + 确定性 LCG 抖动，任何切分方式输出字节不变）；
(2) 主渲染路径的大块 D2H 用 pinned 内存（cudaMallocHost）；(3) 写出阶段
单独计时（wall clock，CPU 工作不用 GpuTimer）。

**实测**（4000x5664 16-bit = 22.6MP / 6800 万样本，热态 A/B 各两遍）：
整体 1.8~2.0s -> 0.96s（2x）；写出阶段（encode + CRC/adler + 落盘）
~1.5s -> 0.55s（2.7x）。分解：field 164ms、post 9.5ms、write 548ms——
encode 里的每样本一次 `std::pow` 是曾经的大头，现在 write 里剩的是
CRC32/adler32 两遍全帧串行扫描 + 135MB fwrite。

**决定**：不把 encode 搬去 GPU。`std::pow` 是超越函数，设备侧 powf 只有
2 ulp 精度，GPU encode 会让 PNG 字节随显卡型号漂移（±1 LSB）——渲染
浮点仍然位级全等，但「同 seed 同图」会从逐字节降级为视觉级。项目卖点
是可复现，2x 不值得。

**教训**：并行化不改变结果的条件是**逐样本纯函数**——tpdfDither 用
(i) 的确定性 LCG 而不是线程局部 RNG，切分才安全。给 RNG 换线程局部
状态的那一刻，输出就开始依赖线程数了。
